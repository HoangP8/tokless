## Installation

### Manual

<img src="assets/install.svg" width="100%" alt="install" />

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/HoangP8/tokless/main/scripts/install.sh | bash
```

**Windows (PowerShell)**

```powershell
irm https://raw.githubusercontent.com/HoangP8/tokless/main/scripts/install.ps1 | iex
```

Interactive install detects installed harnesses. First pick tools, then pick harnesses:

```bash
tokless                              # interactive: choose tools, then harnesses
tokless --agents claude,opencode     # wire just these harnesses
tokless --tools rtk,codegraph        # wire just these tools
```


### MCP tools

Three tools run as MCP servers. Headroom and rtk wire through their own mechanisms (proxy, hooks, plugins) — no MCP needed.

Upstream those three expose **29 tools**. Tokless spawns each server through a bounded proxy that filters its tool list, so **12 land in your context — 17 are trimmed automatically**, at install, nothing to configure.

```text
MCP Tools
├── CodeGraph · 1/1
│   └── codegraph_explore
├── Context Mode · 6/11
│   ├── ctx_execute
│   ├── ctx_batch_execute
│   ├── ctx_execute_file
│   ├── ctx_index
│   ├── ctx_search
│   └── ctx_fetch_and_index
└── ProjectMem · 5/17
    ├── log_issue
    ├── record_attempt
    ├── record_fix
    ├── add_decision
    └── add_note
```

### What gets trimmed

| Server | Upstream | Kept | Trimmed | Why |
| :--- | :---: | :--- | :--- | :--- |
| CodeGraph | 1 | ✅ 1 | — | one tool, nothing to cut |
| Context Mode | 11 | ✅ 6 | ❌ `ctx_stats` · `ctx_doctor` · `ctx_upgrade` · `ctx_insight` · `ctx_purge` | diagnostics and package maintenance — not part of a coding turn |
| ProjectMem | 17 | ✅ 5 | ❌ `current_project` · `get_context` · `get_global_gotchas` · `get_instructions` · `get_issue` · `get_plan` · `get_project_map` · `get_score` · `get_summary` · `list_projects` · `precheck_file` · `search_events` | its reads arrive before the first prompt |

**ProjectMem is the case that matters.** Its 12 read tools (`get_summary`, `get_plan`, …) are replaced by a memory block pushed at session start — hook, plugin/extension, or rule file depending on the harness. Nothing to call: only the 5 writers stay on the list. `tokless doctor` reports the exposed set.

## Usage

```bash
tokless                           # install + wire everything (safe to re-run)
tokless --agents claude,codex     # wire only these harnesses
tokless --tools rtk,codegraph     # wire only these tools
tokless --dry-run                 # preview every write, change nothing

tokless update                    # upgrade CLI + all tools
tokless self-update               # upgrade the tokless binary only
tokless doctor                    # health: tools, harnesses, routes
tokless doctor --fix              # start proxy / build index, interactively
tokless info                      # install paths, config locations
tokless index                     # build this project's codegraph index

tokless disable --agents claude   # unwire harnesses (keep installed tools)
tokless disable --uninstall       # unwire + remove installed binaries
tokless uninstall                 # same as disable --uninstall
tokless proxy up | down | status  # headroom proxy (accepts --agents)
```

## Configuration

### How the tools actually work

Wiring is the product: after install, everything runs on its own — no runtime commands from you.

| Tool | How | When |
| :--- | :--- | :--- |
| principles · caveman · ponytail | Instruction block (rules file) | every prompt — always in context |
| rtk | hook · plugin · extension · cordis patch | every Bash command — rewrite + compress output |
| headroom | local HTTP proxy + route in config | every model API call — compress prompts, route BYOK + OAuth |
| codegraph | MCP server (`codegraph_explore`) | on demand; index builds at first connect |
| context-mode | MCP server (`ctx_*`) | on demand — large files / logs stay out of context |
| projectmem | MCP server + context injection | ~2000-token memory block at session start |

```text
INSTALL ─┬─ rules block      principles · caveman · ponytail
         ├─ MCP entries      codegraph · context-mode · projectmem
         ├─ rtk mechanism    hook · plugin · extension · patch
         └─ headroom route   local proxy 127.0.0.1:8787

SESSION ─┬─ codegraph index  built on first connect
         └─ projectmem block injected before the first prompt

WORK ────┬─ prompt → rules + project memory ride along every turn
         ├─ Bash   → rtk rewrites the command and compresses output
         ├─ think  → codegraph_explore: source, callers, blast radius
         ├─ big    → ctx_* keeps large files and logs out of context
         └─ API    → headroom compresses prompts, routes BYOK + Grok OAuth
```

Without tokless, the harness re-reads the raw tree every session, Bash output lands uncompressed, and nothing survives between sessions. Tokless inverts all three: indexed code, compressed commands, persistent memory.

### How tokless connects to harnesses × 8 tools

**Instruction** = markdown block · **Rule** = project rule file · **Hook** = PreToolUse / SessionStart command · **Plugin** = JS/TS plugin · **Extension** = harness extension API · **Patch** = cordis insert (dsh) · **MCP** = Model Context Protocol server.

### Headroom — the local proxy

Headroom is the one tool with no MCP. It is a local HTTP proxy between your harness and the provider: prompts pass through, get compressed, and continue to the original provider. Tokless wires the route at install and starts the daemon.

```text
harness → 127.0.0.1:8787 (Headroom) → provider
```

| Port | Role |
| :--- | :--- |
| `8787` | Main proxy — `anthropic-native` (Claude Code) + `gemini-native` (Antigravity) + `openai-compatible` (Grok BYOK; Copilot reaches it via its `8790` / `8789` wrappers) |
| `18787` | BYOK gateway — named providers (`qwencoder`, `nvidia_nim`, `cliproxyapi`, `cline`) with your own keys |
| `28787` | Grok OAuth — Headroom-owned login proxy |
| `8790` / `8789` | Copilot CLI / VS Code wrappers |

Grok uses Headroom on both paths: its BYOK `base_url` is rewritten to the shared daemon (`8787/v1`), and its OAuth login runs on a Headroom-owned proxy (`28787`). Cursor's proxy route is deprecated and Amp is never auto-wired — those two stay on their native provider.

Manage it with `tokless proxy up | down | status`. `--agents` scopes any of them to one harness, and `down --agents <list>` leaves shared Headroom running for the rest.
